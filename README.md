# Trueful チーム開発ガイド

Trueful（https://github.com/Trueful/Trueful）を3人で共同開発するための資料です。
全員「プログラミングはできるけど、Git と GitHub での共同開発は初めて」という前提で書いています。

このリポジトリ自体が **練習場** も兼ねています。資料の誤字を直したり、自己紹介を追加したりして、本番（Trueful）の前にここで Pull Request の流れを体験してください。

## 最初の練習課題

1. [環境構築](docs/02-setup.md) を済ませて、このリポジトリをクローンする
2. [作業の流れ](docs/03-daily-workflow.md) に沿って、`members/自分のGitHubユーザー名.md` を作る（自己紹介を数行）
3. Pull Request を出して、他の2人のどちらかにレビューしてもらう
4. 承認されたらマージする
5. 3人全員の自己紹介が揃ったら、わざと同じ行を編集して **コンフリクトを起こして解決する練習** もしてみる（[困ったとき](docs/05-troubleshooting.md#コンフリクトが起きた) 参照）

ここまでできたら、Trueful 本体の作業に進んで大丈夫です。

## 大原則（これだけは覚えておく）

- **main には直接触らない。** 必ずブランチを作って Pull Request を出す
- **迷ったら手を止めて Discord で聞く。** Git はコミットさえしてあれば、ほとんどのことは元に戻せる。慌てて謎のコマンドを打つのが一番危ない
- **秘密情報（APIキー、パスワード、`.env`）は絶対にコミットしない。** Trueful は Public リポジトリなので、世界中に公開される
- 楽しくやる。ミスは練習の一部

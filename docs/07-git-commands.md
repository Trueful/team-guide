# 7. Git コマンド集

目的別に並べた早見表です。普段は VS Code のボタンで操作してOKですが、「このボタンは裏で何をしているのか」を知りたいときや、困ったときに引いてください。

## 危険度の見方

| 印 | 意味 |
|---|---|
| 🟢 | 安全。何度打っても何も壊れない |
| 🟡 | 手元の状態が変わる。意味を分かって使う |
| 🔴 | 変更が消える可能性がある。**Discord で聞いてから使う** |
| ⛔ | このチームでは使わない |

## 表の中の書き方

- `<ブランチ名>` のような `< >` は「ここに自分の値を入れる」という意味。`< >` 自体は打たない
- 例：`git switch <ブランチ名>` → 実際に打つのは `git switch feature/12-tab-group`

---

## 状況を確認する（全部 🟢）

迷ったら、まずこの中のどれかを打つ。

| コマンド | 何をする | VS Code での場所 |
|---|---|---|
| `git status` | 今どのブランチにいて、何が変更されているか | ソース管理パネル |
| `git log --oneline` | コミット履歴を1行ずつ表示（`q` で終了） | Git Graph 拡張 |
| `git log --oneline --graph --all` | 全ブランチの分岐を図で表示 | Git Graph 拡張 |
| `git diff` | まだステージしていない変更の中身 | ソース管理でファイルをクリック |
| `git diff --staged` | ステージ済み（次にコミットされる）変更の中身 | 同上 |
| `git branch` | 手元のブランチ一覧（`*` が今いる場所） | 左下のブランチ名をクリック |
| `git branch -a` | GitHub 側も含めた全ブランチ一覧 | 同上 |
| `git remote -v` | 接続先の GitHub の URL | ― |
| `git show <コミットID>` | 特定のコミットの内容 | Git Graph でクリック |

> `git log` などで画面が切り替わって戻れなくなったら、`q` を押すと抜けられます。

## 最初に一度だけ

| コマンド | 何をする | 危険度 |
|---|---|---|
| `git config --global user.name "<名前>"` | コミットに記録される名前を設定 | 🟢 |
| `git config --global user.email "<noreplyアドレス>"` | コミットに記録されるメールを設定 | 🟢 |
| `git config --global --list` | 設定の確認 | 🟢 |
| `git clone <URL>` | GitHub のリポジトリを手元にコピー | 🟢 |

## 毎回の作業

[作業の流れ](03-daily-workflow.md) の順番どおりに並べています。

| 手順 | コマンド | 何をする | 危険度 |
|---|---|---|---|
| ② | `git switch main` | main ブランチに移動 | 🟡 |
| ② | `git pull` | GitHub の最新を取り込む | 🟡 |
| ③ | `git switch -c <ブランチ名>` | 新しいブランチを作って移動（詳しくは [ブランチを作る](#作る)） | 🟢 |
| ④ | `git add <ファイル名>` | 指定ファイルをステージ | 🟢 |
| ④ | `git add .` | 変更を全部ステージ（**実行前に `git status` で中身を確認**） | 🟢 |
| ④ | `git commit -m "<メッセージ>"` | コミットする | 🟢 |
| ⑤ | `git push -u origin <ブランチ名>` | 初回の push（GitHub にブランチを作る） | 🟢 |
| ⑤ | `git push` | 2回目以降の push | 🟢 |
| ⑨ | `git branch -d <ブランチ名>` | マージ済みのブランチを削除 | 🟢 |

`git branch -d` はマージされていないブランチだと「消していいの？」と止めてくれるので安全です。

## ブランチを作る・移動する・消す

### 作る

**必ず「main を最新にしてから」作ります。** 古い main から作ると、後でコンフリクトの原因になります。

```bash
git switch main                       # 1. main に移動
git pull                              # 2. main を最新にする
git switch -c feature/12-tab-group    # 3. ブランチを作って、そこに移動
git branch                            # 4. 確認（* が新しいブランチについていればOK）
```

| コマンド | 何をする | 危険度 |
|---|---|---|
| `git switch -c <ブランチ名>` | 今いる場所から新しいブランチを作って移動 | 🟢 |
| `git branch <ブランチ名>` | ブランチを作るだけ（移動はしない。作ったのに移動し忘れる事故が多いので、上の `switch -c` を使う） | 🟢 |

ブランチ名は `種類/Issue番号-短い説明`（例：`feature/12-tab-group`）。詳しくは [チームルール](04-team-rules.md#ブランチ名)。

作ったブランチは、最初の push まで GitHub には存在しません。

| コマンド | 何をする | 危険度 |
|---|---|---|
| `git push -u origin <ブランチ名>` | GitHub にもブランチを作る（初回だけ。以降は `git push` だけでOK） | 🟢 |

### 移動する

| コマンド | 何をする | 危険度 |
|---|---|---|
| `git switch <ブランチ名>` | 既存のブランチに移動 | 🟡 |
| `git switch -` | 直前にいたブランチに戻る | 🟡 |

コミットしていない変更があると移動できないことがあります。その場合は、コミットするか [作業を一時退避する](#作業を一時退避する) を使います。

他のメンバーのブランチを手元で見たいとき：

```bash
git fetch                     # GitHub の最新状況を取得
git switch feature/15-xxx     # 相手のブランチ名で移動（自動で手元にも作られる）
```

見るだけならOK。そこに push するなら一声かける。

### main の変更を取り込む

| コマンド | 何をする | 危険度 |
|---|---|---|
| `git fetch` | GitHub の最新状況を確認だけする（手元のファイルは変わらない） | 🟢 |
| `git merge origin/main` | GitHub の main の変更を今のブランチに取り込む | 🟡 |
| `git merge --abort` | コンフリクトしたマージを中止して元に戻す | 🟢 |

### 名前を変える

| コマンド | 何をする | 危険度 |
|---|---|---|
| `git branch -m <新しい名前>` | 今いるブランチの名前を変える（push 前なら気軽にOK） | 🟢 |

push 済みのブランチの名前を変えるのは手間がかかるので、その場合は気にせずそのまま使うか、Discord で相談。

### 消す

| コマンド | 何をする | 危険度 |
|---|---|---|
| `git branch -d <ブランチ名>` | 手元のブランチを削除（マージ済みのものだけ消せる） | 🟢 |
| `git fetch --prune` | GitHub で消されたブランチの情報を手元からも掃除する | 🟢 |

GitHub 側のブランチは、PR をマージすると自動で削除されます（オーナー設定済み）。今いるブランチは消せないので、先に `git switch main` してから消します。

## 作業を一時退避する

| コマンド | 何をする | 危険度 |
|---|---|---|
| `git stash` | コミットしていない変更を一時的に退避 | 🟡 |
| `git stash list` | 退避中の一覧 | 🟢 |
| `git stash pop` | 退避した変更を戻す | 🟡 |

ブランチを切り替えたいけど、まだコミットしたくないときに使います。退避したことを忘れがちなので、なるべく早く `pop` すること。

## 取り消す・直す

**まだ push していないもの** と **push 済みのもの** で使うコマンドが違います。

### まだ push していない

| コマンド | 何をする | 危険度 |
|---|---|---|
| `git restore --staged <ファイル名>` | ステージを取り消す（変更は残る） | 🟢 |
| `git restore <ファイル名>` | ファイルの変更を捨てて、最後のコミットの状態に戻す | 🔴 |
| `git commit --amend -m "<メッセージ>"` | 直前のコミットのメッセージを直す | 🟡 |
| `git reset --soft HEAD~1` | 直前のコミットを取り消す（変更は手元に残る） | 🟡 |

`git restore <ファイル名>` はコミットしていない変更を消します。消した変更は Git では戻せません。

### push 済み

| コマンド | 何をする | 危険度 |
|---|---|---|
| `git revert <コミットID>` | そのコミットを打ち消す新しいコミットを作る（履歴は消えない） | 🟡 |

push 済みのものは「消す」のではなく「打ち消しを追加する」のが鉄則です。main にマージ済みなら、GitHub の PR 画面の「Revert」ボタンでも同じことができます。

## 救出する

| コマンド | 何をする | 危険度 |
|---|---|---|
| `git reflog` | 自分が過去にいた場所の全記録（`q` で終了） | 🟢 |
| `git switch -c rescue <コミットID>` | 過去の時点を `rescue` ブランチとして復元 | 🟢 |

「コミットが消えた！」と思ったら、まず `git reflog`。詳しくは [困ったとき](05-troubleshooting.md#作業が消えた)。

## その他

| コマンド | 何をする | 危険度 |
|---|---|---|
| `git mv <旧名> <新名>` | ファイル名を変更（大文字・小文字だけの変更もこれで） | 🟢 |
| `git rm --cached <ファイル名>` | ファイルは残したまま、Git の管理から外す（誤ってコミットした設定ファイルなど） | 🟡 |

---

## 🔴 相談してから使うもの

ネットで検索するとよく出てきますが、変更を消せてしまうコマンドです。使う前に Discord で「こういう状況で、これを打とうと思う」と聞いてください。

| コマンド | 何が危ないか |
|---|---|
| `git reset --hard` | コミットしていない変更がすべて消える |
| `git clean -fd` | Git 管理外のファイル（新しく作ったファイルなど）が消える |
| `git restore .` | すべてのファイルの未コミットの変更が消える |
| `git checkout .` | 同上（古い書き方） |
| `git branch -D <ブランチ名>` | マージしていないブランチも強制削除（小文字の `-d` なら安全） |
| `git stash drop` / `git stash clear` | 退避した変更を捨てる |

## ⛔ このチームでは使わないもの

| コマンド | 理由 |
|---|---|
| `git push --force` / `git push -f` | GitHub 上の他人のコミットを消せてしまう。main は設定でブロック済みだが、作業ブランチでも使わない |
| `git rebase` | 履歴を書き換えるので、push 済みのブランチで使うと force push が必要になる。慣れるまでは merge だけで十分 |
| `git filter-branch` / `git filter-repo` | 履歴全体の書き換え。秘密情報の完全削除などでオーナーが判断して行う |

「⛔」のものは悪いコマンドではなく、慣れた人が状況を分かったうえで使うものです。チームで慣れてきたら、ルールを見直して解禁しても大丈夫です。

## 古い書き方について

ネットの記事では、同じ意味で古いコマンドが使われていることがあります。どちらでも動きますが、この資料では新しい方で統一しています。

| 古い書き方 | この資料での書き方 |
|---|---|
| `git checkout <ブランチ名>` | `git switch <ブランチ名>` |
| `git checkout -b <ブランチ名>` | `git switch -c <ブランチ名>` |
| `git checkout -- <ファイル名>` | `git restore <ファイル名>` |
| `git reset HEAD <ファイル名>` | `git restore --staged <ファイル名>` |

`checkout` は1つのコマンドでいろいろなことができてしまい分かりにくかったので、役割ごとに `switch`（ブランチ移動）と `restore`（ファイルを戻す）に分けられました。

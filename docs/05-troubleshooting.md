# 5. 困ったとき

## まず落ち着く

Git は **コミットさえしてあれば、ほぼ何でも元に戻せます**。一番危ないのは、慌ててネットで見つけたコマンドを実行することです。

困ったら：

1. 手を止める
2. `git status` を実行する
3. その結果と「何をしようとしてこうなったか」を Discord に貼る

心配なら、作業フォルダを丸ごと別の場所にコピーしてバックアップしてから触ってもOKです。

## コンフリクトが起きた

2人が同じファイルの同じ場所を変更していると、Git はどちらを採用すべきか決められません。これがコンフリクトです。**壊れたわけではなく、「どっちにする？」と聞かれているだけです。**

ファイルの中はこうなっています：

```
<<<<<<< HEAD
自分の変更
=======
相手（main）の変更
>>>>>>> origin/main
```

### VS Code での解決

1. ソース管理の「マージの変更」欄に、コンフリクトしたファイルが出る
2. ファイルを開くと、該当箇所の上に次のボタンが出る
   - **現在の変更を取り込む**（自分の方を残す）
   - **入力側の変更を取り込む**（相手の方を残す）
   - **両方の変更を取り込む**
3. どれでもなければ、手で書き換えて `<<<<<<<` `=======` `>>>>>>>` の行を消す
4. 全部直したら、アプリが動くか確認
5. ファイルを **＋**（ステージ）→ コミット → push

どちらを残すべきか分からないときは、**相手に聞く**。勝手に相手の変更を消さないこと。

### 途中でやめたいとき

```bash
git merge --abort
```

マージ前の状態に戻ります。

### 予防策

- 作業を始める前に必ず main を最新にする（手順書 ②）
- PR を小さくして、早めにマージする
- 同じファイルを大きくいじるときは Discord で一声かける

## main で作業してしまった

### まだコミットしていない場合

変更はそのまま新しいブランチに持っていけます。

```bash
git switch -c feature/12-tab-group
```

VS Code なら、そのまま左下から「新しいブランチを作成」するだけです。

### main にコミットしてしまった（push はしていない）

main は保護されているので push はできません。次の手順でブランチに移します。

```bash
git switch -c feature/12-tab-group   # 今のコミットを持ったまま新ブランチを作る
git switch main                      # main に戻る
git reset --hard origin/main         # main だけを GitHub と同じ状態に戻す
git switch feature/12-tab-group      # 作業ブランチに戻って続ける
```

> `reset --hard` は、コミットしていない変更を消すコマンドです。1行目で作業がブランチに保存されているので、この順番なら安全です。**不安なら実行前に Discord で聞いてください。**

## push が拒否された

`rejected` や `failed to push some refs` と出た場合。

| 原因 | 対処 |
|---|---|
| GitHub 側に自分の手元にないコミットがある | `git pull` してから、もう一度 `git push` |
| main に push しようとした | 正常です（保護されている）。[main で作業してしまった](#main-で作業してしまった) へ |
| 認証エラー（`Authentication failed` など） | VS Code で GitHub に再サインイン。直らなければ Discord へ |

**ここで `--force` をつけて押し通すのは禁止です。**

---

## 直前のコミットを直したい

**まだ push していない場合のみ**使えます。

メッセージだけ直す：
```bash
git commit --amend -m "feat: 正しいメッセージ"
```

直前のコミットを取り消して、変更は手元に残す：
```bash
git reset --soft HEAD~1
```

push 済みなら、この方法は使いません。気にせず新しいコミットで直してください。PR は Squash されるので、途中の細かいコミットは最終的に1つにまとまります。

---

## push 済みの変更を取り消したい

### まだマージ前の PR の場合

普通に直して、新しいコミットを push すればOKです。

### main にマージ済みの場合

`git revert` で「打ち消しのコミット」を作ります。履歴を消さずに元に戻せる安全な方法です。GitHub では、マージ済み PR の画面にある「Revert」ボタンで、打ち消し用の PR を作れます。

---

## 秘密情報を push してしまった

APIキー、トークン、パスワード、`.env` などを push してしまった場合。**スピード勝負です。**

1. **すぐにそのキー・パスワードを無効化して、新しいものを発行する**（これが最優先。消すより先）
2. オーナーに Discord で連絡する
3. ファイルを削除するコミットをして、`.gitignore` に追加する

Public リポジトリでは、push した瞬間に自動収集ボットに拾われる前提で考えます。ファイルを消しても履歴には残るので、「消したから大丈夫」ではありません。履歴からの完全削除が必要かどうかはオーナーと相談して決めます（自分でやらない）。

> オーナーが「Push protection」を有効にしていれば、GitHub が既知の形式のキーを検知して push を止めてくれます。止められたら、そのファイルをコミットから外してください。

## 作業が消えた

コミットしてあったなら、ほぼ確実に復元できます。

```bash
git reflog
```

自分が過去にいた場所の一覧が出ます。戻りたい時点の番号（例：`a1b2c3d`）を見つけたら：

```bash
git switch -c rescue a1b2c3d
```

`rescue` というブランチにその時点の状態が復元されます。分からなければ `git reflog` の結果を Discord に貼ってください。

コミットしていなかった変更は、Git では戻せません。VS Code の「タイムライン」（エクスプローラー下部）にローカル履歴が残っている場合があります。**こまめにコミットする習慣が一番の保険です。**

---

## ブランチを切り替えられない

`Your local changes would be overwritten` と出る場合、コミットしていない変更があります。

- 今の変更を残したい → コミットしてから切り替える
- 一時的に退避したい → `git stash` で退避、戻ってきたら `git stash pop`

## Mac と Windows の混在で起きること

| 現象 | 原因と対処 |
|---|---|
| 何も変えていないのに全行が変更扱いになる | 改行コードの違い（Mac: LF / Windows: CRLF）。リポジトリの `.gitattributes` で統一済み。それでも起きたら Discord へ |
| ファイル名の大文字・小文字だけ変えたのに反映されない | Mac/Windows はファイル名の大小文字を区別しない。`git mv 旧名 新名` で変更する |
| `.DS_Store` や `Thumbs.db` が変更に出てくる | OS が勝手に作るファイル。`.gitignore` 済みのはず。コミットしない |

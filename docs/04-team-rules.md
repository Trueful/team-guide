# 4. チームルール

「練習のためのチーム」なので、実際の開発現場でよく使われる形に寄せつつ、初心者でも回せるシンプルなルールにしています。やってみて合わなければ、Issue を立てて変えましょう。

## 基本の流れ：GitHub Flow

- `main` は常に「動く状態」を保つ
- 作業は必ずブランチで行い、Pull Request 経由で main にマージする
- **1つの Issue ＝ 1つのブランチ ＝ 1つの PR**
- PR は小さく。目安は「レビューする人が15分で読める量」。大きな機能は Issue を分ける

## ブランチ名

```
種類/Issue番号-短い説明
```

| 種類 | 使うとき | 例 |
|---|---|---|
| `feature/` | 新機能 | `feature/12-tab-group` |
| `fix/` | バグ修正 | `fix/15-crash-on-startup` |
| `docs/` | ドキュメントのみ | `docs/20-update-readme` |
| `refactor/` | 動作を変えない整理 | `refactor/23-split-workspace-service` |
| `chore/` | 設定・依存関係など | `chore/30-update-pnpm` |

- 英小文字とハイフンのみ。日本語・スペースは使わない

## コミットメッセージ

```
種類: 何をしたか（日本語）
```

例：
```
feat: ワークスペースの新規作成フローを追加
fix: 起動時にDBが見つからないとクラッシュする問題を修正
docs: READMEにセットアップ手順を追記
```

| 種類 | 意味 |
|---|---|
| `feat` | 新機能 |
| `fix` | バグ修正 |
| `docs` | ドキュメント |
| `refactor` | リファクタリング（動作は変えない） |
| `style` | 見た目・フォーマットのみ |
| `test` | テスト |
| `chore` | 設定・ビルド・依存関係など |

- 先頭の種類は英語（Conventional Commits という広く使われている形式）、説明は日本語
- 「修正」「更新」だけのメッセージは禁止。何をどうしたかを書く
- コードの中の変数名・関数名は英語

## 言語

- Issue・PR・コメント・コミットの説明：**日本語**
- コード中の識別子：英語
- コードコメント：日本語でOK
- OSS として海外の人から Issue や PR が来たら、英語で対応（翻訳ツールを使ってOK）

## Pull Request とレビュー

- PR を出したら、他のメンバーを1人以上 Reviewer に指定
- **承認（Approve）1つでマージ可能**。オーナーの PR もメンバーがレビューする（全員が同じルール）
- マージは **PR を出した本人** が「Squash and merge」で行う
- レビューはできれば24時間以内に。無理なら「明日見ます」とコメントだけでも

### レビューする人の心得

- 否定ではなく質問・提案の形で書く（「ここは〜の方がいいかも？」「これはどういう意図？」）
- 細かい好みの指摘には `nit:`（nitpick＝些細な指摘）とつける。対応は任意
- よいところも褒める
- 分からないところは「分からない」と書いてOK。それもレビューの価値

### レビューされる人の心得

- 指摘は人格ではなくコードへの意見。気にしすぎない
- 意図があるなら説明する。納得したら直す

## タスク管理とコミュニケーションの使い分け

| 内容 | 場所 |
|---|---|
| やること・バグ・アイデア | **GitHub Issue** |
| コードについての議論 | **PR のコメント** |
| 雑談・ちょっとした相談・急ぎの連絡・通話 | Discord |
| Discord で決まった大事なこと | Issue か PR にコメントで書き残す |

GitHub 上に記録を残すことを優先します。「あれ、どこで決めたっけ？」をなくすためと、GitHub に慣れるためです。

## 禁止事項（取り返しがつかないこと）

| やらないこと | 理由 |
|---|---|
| main への直接 push | 他の人の作業が壊れる（設定でブロック済み） |
| `git push --force`（`-f`） | 他の人のコミットを消せてしまう |
| 秘密情報のコミット | Public なので即世界に公開される。消しても履歴に残る |
| 他人のブランチに勝手に push | 相手の作業とぶつかる。やるなら一声かける |
| 意味の分からないコマンドをネットからコピペして実行 | 特に `reset --hard`、`clean`、`--force` を含むもの。まず Discord で聞く |
| リポジトリの設定変更・削除 | オーナーのみが行う |

## ルールの変え方

このルール自体も、Issue を立てて PR で変更します。練習になるので積極的に提案してください。

# 1. Git と GitHub の基本

## Git と GitHub は別物

| | Git | GitHub |
|---|---|---|
| 何か | ファイルの変更履歴を記録する **ツール** | Git の履歴をネット上で共有する **サービス** |
| どこで動く | 自分のパソコンの中 | インターネット上 |
| たとえ | ゲームのセーブ機能 | セーブデータを共有するクラウド＋掲示板 |

Git だけでも一人で履歴管理はできます。GitHub を使うことで、3人の履歴を1か所に集めて、話し合いながら合体させられるようになります。

## 全体像

```
 あなたのPC                                   GitHub
┌──────────────────────────────┐          ┌──────────────┐
│ 作業フォルダ ─(add)→ ステージ ─(commit)→ ローカルリポジトリ │ ─(push)→ │ リモートリポジトリ │
│                                   ←──────────(pull)────── │ (origin)     │
└──────────────────────────────┘          └──────────────┘
```

1. ファイルを編集する（作業フォルダ）
2. 「今回セーブに含める変更」を選ぶ（**ステージ / add**）
3. セーブする（**コミット / commit**）。ここまでは自分のPCの中だけ
4. GitHub に送る（**プッシュ / push**）。ここで初めて他の人に見える
5. 他の人の変更を受け取る（**プル / pull**）

## ブランチ：並行世界

**ブランチ** は「本流から分岐した作業用の世界」です。

```
main     ●───●───────────●────  ← 常に動く状態を保つ本流
              \         /
feature/xxx    ●───●───●         ← 自分の作業場。壊しても main は無事
```

- `main` … みんなの共有の本流。常に「動く状態」を保つ
- 作業用ブランチ … 1つの作業ごとに作る。自由に試せる
- 作業が終わったら、作業用ブランチを main に合体（**マージ**）する

3人が同時に main を直接いじると、お互いの変更を上書きしあって大混乱になります。だから各自がブランチで作業して、確認してから main に合体させます。

## Pull Request（PR）：合体の申請

**Pull Request** は「このブランチを main に合体させてください」という申請です。GitHub 上で作ります。

- 何を変えたかが差分で見える
- 他のメンバーがコメント・質問・承認できる（**レビュー**）
- 承認されたらボタン1つでマージできる

名前に Pull が入っていますが、`git pull` とは別物です。「取り込んで（pull して）ください、というお願い」という意味です。

## Issue：やることリスト兼掲示板

**Issue** は GitHub 上の「課題票」です。バグ報告、機能のアイデア、作業の割り振りに使います。番号（`#12` など）が振られ、PR から `Closes #12` と書くと、マージ時に自動で閉じられます。

## 用語集

| 用語 | 意味 |
|---|---|
| リポジトリ（repo） | プロジェクトの保管庫。ファイル＋全履歴 |
| リモート / origin | GitHub 側のリポジトリ。`origin` はその呼び名 |
| クローン（clone） | GitHub のリポジトリを自分の PC に丸ごとコピー |
| コミット | 変更のセーブポイント。メッセージ付き |
| ステージ（add） | 次のコミットに含める変更を選ぶこと |
| プッシュ（push） | 自分のコミットを GitHub に送る |
| プル（pull） | GitHub の新しいコミットを受け取る |
| フェッチ（fetch） | GitHub の状況を確認だけする（手元は変えない） |
| ブランチ | 分岐した作業ライン |
| マージ | ブランチ同士を合体させる |
| コンフリクト | 同じ場所を別々に変更していて、自動で合体できない状態 |
| PR（Pull Request） | マージの申請＋レビューの場 |
| Issue | 課題・タスク・議論のチケット |
| HEAD | 「今いる場所」。今チェックアウトしているコミット |
| ステータス | `git status` で見られる「今どうなってるか」 |

## 覚えるコマンドは最小限でOK

普段は VS Code のボタンで操作します。ただし困ったときに状況を共有するため、次の3つだけは覚えてください。

```bash
git status          # 今どうなってる？（一番大事。迷ったらまずこれ）
git log --oneline   # コミットの履歴を1行ずつ見る
git branch          # ブランチ一覧（* が今いるブランチ）
```
